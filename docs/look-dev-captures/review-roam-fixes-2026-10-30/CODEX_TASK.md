## 修正 1：大门不要开进浴室

**问题**

`current/05` 里，一进门就是浴室，第一印象很差。原因有两个：

- look-dev 的 `house` 户型把客厅放在了后排，没有正面墙；
- `getManorFacadeLayout` 的兜底规则「任意正面墙」选中了浴室。

**1a. 改入口选择规则**（`public/js/home-manor-layout.js`，按房间布局的那条分支）

把现在的 5 级优先改成下面的排序：

1. 候选：所有房间的正面墙和右侧墙，墙段长度要放得下门（门宽见 `getManorDoorWidth`）。
2. 先比**房间类型**，数字小的优先：

| 优先级 | 房间类型（按 `baseKind`） |
| --- | --- |
| 0 | 门厅 hallway |
| 1 | 客厅 living |
| 2 | 餐厅、厨房 |
| 3 | 书房和其他 |
| 4 | 卧室 |
| 5 | 浴室、卫生间 |

3. 类型相同时，正面墙优先于右侧墙。
4. 再相同时，保持现在的顺序。

效果：门厅和客厅的结果和现在完全一样；浴室只有在没有别的房间可选时才会成为入口。

**生效范围**：只在 warm 主题下生效。这条规则也决定外观上大门的位置，如果对所有主题生效，默认主题和 Toy 的基准图会变。实现方式由你决定，回传时说明。

**测试**：补单元测试，至少覆盖——

- 只有浴室有正面墙、厨房有右侧墙 → 选厨房；
- 客厅有正面墙 → 选客厅（和现状一致）；
- 只剩浴室 → 选浴室；
- 非 warm 主题 → 结果和现在一模一样。

**1b. 调整 look-dev 的 `house` 户型**（`scripts/qa/look-dev-fixtures.mjs`）

1. 把客厅和卧室两排对调，让客厅在前排：
   - 客厅改为 `R('living', -2.8, 2.6, …)`；
   - 卧室改为 `R('bedroom', -2.8, -2.6, …)`；
   - 两个房间里的家具跟着在 z 方向平移 ±5.2 m，相对位置不变。
2. 厨房、浴室不动。
3. 调整后，按现有规则入口就会落在客厅正面墙上。

这一步只影响 look-dev 和参观审阅页。上一包的 12 个验收画面需要按新户型重拍（见文末验收）。

## 修正 2：从屋里回看大门，门外一片白

**问题**

`current/07` 里，门洞外几乎是纯白色。原因是进屋后关掉了太阳光、曝光提到 1.22，门外的地面和背景被一起提亮到过曝。窗户外面也有同样的问题。

**要求**

从屋里看出去，室外应该是正常的白天室外：

- 能看出门口台阶、地面和远处的天色或背景；
- 比室内稍亮，但不过曝。

**验收标准**（在新的 07 画面中测量）

1. 门洞区域的平均亮度（sRGB 像素值 0–1）在 0.70–0.88 之间。
2. 门洞区域内亮度标准差 ≥ 0.04，也就是不能是一块平的白。
3. 门洞区域内亮度 ≥ 0.97 的像素占比 < 10%。
4. 室内部分（墙、门板）的亮度和上一版相比变化不超过 ±5%。

**实现方式由你决定**，可选做法比如：

- 进屋时把背景换成单独的天色渐变，按室内曝光做补偿；
- 门外可见的地面、台阶材质在室内状态下按 1/1.22 补偿；
- 门外使用独立的灯光层。

原则：室外补偿不能影响室内的灯光数值；出屋后全部恢复原值。

## 修正 3：落地灯开了看不出来

**问题**

`current/11` 里，落地灯开着，但画面上几乎看不出变化，被吸顶灯盖住了。

**要求**

1. 灯罩里的点光源：强度 7 → 16，距离 6 → 5，衰减 2。
2. 灯罩自发光 `#ffc477`，强度 0.8 → 1.6。灯罩要明显比周围墙面亮，看起来像「透光的灯罩」。
3. 灯罩下方地面有一圈暖色光斑：再加一盏朝下的聚光灯，或者在灯罩下沿放第二个点光源，二选一。
   - 光斑直径约 1.2–1.6 m；
   - 不投阴影，避免多一张阴影贴图；
   - 灯的数量仍然固定，开关只改强度。
4. 吸顶灯数值不变。

**验收**

新增一对同机位截图：`11a` 落地灯关、`11b` 落地灯开，吸顶灯都开着。

- 灯后墙面上，以灯为中心 1 m 范围内，平均亮度提升 ≥ 25%；
- 灯罩区域平均亮度 > 同画面墙面平均亮度；
- 地面光斑肉眼可见。

## 修正 5：参观模式的界面文案用中文

**问题**

`current/01`、`current/05` 里，界面全是英文（Visit、Viewing: Exterior、Slow orbit、Leave、Click the door to enter、帮助卡等）。这是面向中国课堂的产品，界面必须是中文。

**要求**

产品实际运行时（`?theme=warm` 的应用页和参观审阅页）显示下表的中文文案：

| 位置 | 文案 |
| --- | --- |
| 图标坞第 4 项 | 参观 |
| 左上标题 | `{学生名}的家 · 自由参观`（审阅页用「示例的家 · 自由参观」） |
| 右上状态 | 正在看：外观 / 正在看：室内 |
| 底部模式按钮 | 自动 / 外观 / 室内 |
| 镜头按钮 | 慢慢转 / 回到全景 / ? |
| 悬停大门 | 点门进屋 |
| 室内退出按钮 | 出门 |
| 室内顶部提示条 | W S 前后 · A D 左右 · E Q 升降 · Shift 加速 · 拖动看四周 · 点地面走过去 · 点水龙头、马桶、灯、抽屉、柜门、灶台可以用 · 可以穿墙 · Esc 出门 |
| 互动提示 | 开水龙头 / 关水龙头、冲水、开灯 / 关灯、开落地灯 / 关落地灯、拉开抽屉 / 关上抽屉、打开柜门 / 关上柜门、点火 / 关火 |

**帮助卡**

外观状态：

- 左键拖动：绕着房子转
- 滚轮：推近 / 拉远
- 右键拖动：平移
- W A S D：平移镜头
- Q / E：绕着房子左右转
- 空格：自动慢转
- R：回到全景
- 在外观里点大门，门会打开，你会走进屋里

室内状态：

- W / S：前后
- A / D：左右
- E 或空格 / Q：升降
- ← / →：原地转身
- Shift：加速
- 拖动：看四周
- 滚轮：前后移动
- 点地面：走过去
- 点东西：使用它
- Esc：出门

**与公开仓库英文化规则的关系**

如果公开仓库的规则要求公开副本保持英文（上一份交付说明里提到的 public-copy 规则），请按现有的文案机制处理：

- 中文是产品文案，公开副本可以另行转换；
- 不要把中文硬编码在逻辑代码里，用项目现有的文案表或 i18n 方式；
- 回传时说明中文在哪个构建或哪个参数下生效，并附上中文界面的截图。

**验收**：截取中文界面的截图，至少包括：

- 外观环绕；
- 悬停大门；
- 刚进屋（带提示条）；
- 一处互动悬停提示；
- 打开的帮助卡（外观、室内各一张）。
