# Homeworld 任务包：自由参观模式（2026-10-30）

本包是一项独立任务，说明、参考图和原型代码都在包内。

- 仓库：`Tyresee/homeworld-source-review`，请基于最新的 main 开发。
- 先后顺序：前两个包（「墙面系统 + 界面改版」「墙体剖切 0.5 m」）如果还没做完，先完成它们，再做本包。

总体约束：

- 所有改动只在 `?theme=warm` 下生效；默认主题和 `?theme=toy` 的外观、行为都不变。
- 参观模式只用来「看」和「玩」，不改存档、价格、SKU、积分、碰撞和可走区域，也不改家具摆放规则。
- 抽屉开没开、灯开没开之类的互动状态，只在本次参观中有效，不写进存档。
- 包内 `prototype/` 是审阅方做的**临时原型**，只用来表达意图，不要直接合并进 `public/js`。
- 不部署。

## 0. 导入参考资料（单独提交一次）

把本包中的 `reference/` 和 `prototype/` 放进仓库，路径为 `docs/look-dev-captures/review-roam-2026-10-30/`。

## 1. 背景与原型

项目负责人希望把房子当作一件 3D 作品来参观，体验要像游戏里漫游，不是固定的机械视角：

1. 在外面绕着房子看；
2. 点大门，门打开，镜头走进去；
3. 进屋后可以自由移动（无碰撞，可以穿墙）；
4. 屋里的东西可以互动：水龙头、马桶、灯、抽屉、柜门、灶台。

原型是一个独立页面，可以本地运行：

```
cd prototype/roam-site
python3 -m http.server 18870
# 浏览器打开 http://127.0.0.1:18870/test.html
```

关于原型的几点说明：

- 场景来自 look-dev 的 `house` 视图，由 `prototype/tools/export-house.js` 导出（`scene.toJSON()` → gzip → base64，存为 `house.b64.txt`）。
- `prototype/look-dev-hooks/` 里是导出时用到的两个 look-dev 改动，仅供参考。
- 所有逻辑都在 `roam.js`，后文规格中的数值都取自这里。

原型里有几处是为了凑测试场景做的**临时手段，正式实现不要照抄**：

| 原型里的做法 | 正式实现应该怎么做 |
| --- | --- |
| 室内整体旋转 180°，让大门对着客厅 | 不旋转。大门通向 `getManorFacadeLayout(...).entrance.room` 指定的房间。 |
| 运行时把落地灯挪到客厅角落 | 不挪，家具用存档里的位置。 |
| 运行时把外墙实心块挖空，把拱形门框重建成拱圈，把门板挂到转轴上 | 改 `home-estate-manor.js` 的建模（见 3.2）。 |
| 按外墙主体中心对齐 manor 和室内地板 | 用游戏里已有的坐标关系，不要另做对齐。 |
| `window.__ROAM_SLOW`、`__roam` 调试接口 | 不需要。 |

## 2. 入口与退出

1. 在左下角图标坞（上一包任务 2 新增）的「整栋」右侧，加第 4 个图标「参观」，用小房子加眼睛的插画，下方配短字。快捷键 `4`。
2. 进入参观模式后：
   - 隐藏编辑相关的界面：右键菜单、拖动摆放、遥控器、顶部状态条；
   - 保留：左上角标题、右上角「正在看：外观 / 室内」、底部「自动 / 外观 / 室内」切换、「慢慢转」「回到全景」「?」；
   - 这一套布局见 `reference/01`。
3. 退出：
   - 点图标坞中的其他视图；
   - 或在外观环绕状态按 `Esc`。
4. 退出后回到原来的视图和正交相机，相机参数要完全恢复。

## 3. 规格

### 3.1 外观环绕（参考图 01、02）

参观模式使用单独的**透视相机**；游戏原有的 OrthographicCamera 不动。

**相机参数**

- 视角 FOV 38°。
- 环绕控制：阻尼 0.08，缩放朝向鼠标位置（zoomToCursor），距离 1.6–45 m，最大俯仰 86°，旋转速度 0.7。
- 「回到全景」位置：`中心 + (0.95, 1.05, 1.25) × 房子最大边长`，过渡 0.7 s。

**操作**

- 左键拖：绕房子转。
- 滚轮：推近或拉远。
- 右键拖：平移。
- W A S D：平移。
- Q / E：绕房子左右转。
- 空格：自动慢转，速度 0.6。
- R：回到全景。

**自动切换外观 / 室内**

- 镜头到目标点的距离 > 1.55 × 房子最大边长时，显示外观（manor 模型）；否则显示室内（房间、家具、机器人）。
- 底部按钮可以固定为「外观」或「室内」。

**室内状态下的墙**

- 如果一面墙所在的平面把镜头和目标点隔开（两者分别在墙的两侧），这面墙就剖切到 0.5 m 高，顶上压 4.5 cm 厚、颜色 `#4a3f37` 的切面，墙上挂的东西同时隐藏。
- 镜头移动后重新计算。
- 剖切规则沿用上一包（墙体剖切）。

**渲染**

- 按需渲染：只有画面变化时才渲染。
- 阴影使用 PCF，`shadow.bias = -0.0006`，`normalBias = 0.035`，避免墙面出现阴影条纹。

### 3.2 点门进屋（参考图 03、04、05）

**悬停**

- 只在外观状态下检测。鼠标射线命中门板或门上的把手时：
  - 鼠标变成手指；
  - 门板加发光 `#6b3a17`；
  - 鼠标旁出现提示「点门进屋」。

**点击**

- 按下到松开的移动距离 < 6 px，才算点击，否则当作拖动。
- 点击后按以下顺序播放：

| 步骤 | 时长 | 内容 |
| --- | --- | --- |
| 1 | 1.5 s | 镜头移到门外 2.8 m 处，眼高 1.45 m，看向门中心（高 1.2 m）；FOV 38 → 50 |
| 2 | 0.25 s | 停顿；这时屋内已经显示出来，透过门缝能看到 |
| 3 | 1.2 s | 门板绕门轴向屋内转开 1.8 rad；门轴在门板一侧的竖边上 |
| 4 | 1.8 s | 镜头走进门内 2.0 m，视线转向屋子深处；FOV 50 → 68；穿过外墙那一刻切换到室内 |

- 播放期间隐藏底部按钮和右上角状态，不响应其他输入。
- 所有缓动使用 smoothstep。

**模型改动**（改 `home-estate-manor.js` 等建模代码，不要在运行时修补）

1. **外墙主体**：现在是一个实心盒体，改成真正有墙厚的四面墙。厚度约 0.2 m，入口那面墙在门的位置开一个真实门洞。这一条只在参观模式下需要，可以另生成一份参观用模型，也可以给 `createEstateManor` 加一个参数。
2. **拱形门框**：现在是实心块，门板贴在它前面。改成中间镂空的拱圈，洞口和门板轮廓一致（矩形加半圆顶）。
3. **门板**：做成独立物体，挂在门轴节点上。双面渲染，或者给它厚度，否则转开后从外面看会消失。
4. **把手**：门上的把手（金色条和圆钮）跟着门板一起转。
5. **室内入口墙**：通向 `entrance.room` 的那面外墙，在参观模式下要在同一位置开一个门洞，洞宽与门板宽相同，洞高到门板顶。室内墙在其他模式下不变。

### 3.3 进屋后的自由相机（参考图 05、06、07）

**基本规则**

- 第一人称自由相机，**没有碰撞**，可以穿墙、穿家具、飞上天。
- 默认眼高 1.45 m，FOV 68°。
- 相机高度限制在 0.25–30 m。

**操作**

| 操作 | 效果 |
| --- | --- |
| W / S，或 ↑ / ↓ | 沿视线方向前进或后退（视线朝上就往上飞） |
| A / D | 左右平移 |
| E 或空格 / Q | 上升 / 下降 |
| ← / → | 原地转身，1.8 rad/s |
| 按住 Shift | 加速：普通 2.6 m/s，加速 6 m/s |
| 左键拖动 | 看四周：水平 0.0045 rad/px，垂直 0.0035 rad/px，俯仰限制 ±1.45 rad |
| 滚轮 | 沿视线前后移动 0.45 m |
| 点地面 | 镜头滑到那个位置，高度不变，同时转向那个方向；速度 3 m/s，时长限制在 0.35–2.6 s |
| 点墙或家具（不可互动的） | 滑到它前方 0.9 m 处停下 |
| 点可互动的东西 | 执行互动（见 3.5），不移动 |
| Esc，或右下角「出门」 | 退出（见下） |

- **键盘必须按物理键识别**（`KeyboardEvent.code`，例如 `KeyW`），不能按 `key`。否则开着中文输入法时 `key` 是 `Process`，WASD 全部失灵。这是负责人实际遇到的问题。
- 窗口失去焦点时清空按键状态。
- 每帧时间上限 0.1 s，避免掉帧时移动变慢。

**室内 / 室外显示**

- 相机在外墙主体的范围内，而且低于墙顶时，算「室内」：
  - 隐藏 manor 外壳；
  - 显示房间的四面外墙（入口墙换成带门洞的版本）、吊顶和室内灯光。
- 相机在外面时，算「屋外」：显示 manor 外壳，透过门洞能看到屋里。
- 穿墙时两种显示直接切换。
- 吊顶是一块朝下的平面，高度在墙顶下方 1.5 cm。

**出门**

1. 1.2 s 退到门外 2.8 m，看向门，FOV 回到 38；
2. 0.8 s 关门；
3. 回到外观环绕，并执行「回到全景」。

### 3.4 室内光照（参考图 05、06、12）

问题：屋里原来是被太阳直射的，墙上有斜的日光块。负责人认为这和室内灯光不协调，先是嫌暗，调亮后通过。进屋（室内显示）时改为下面这套光照，出屋恢复原值：

| 项目 | 室内 | 屋外 / 环绕（原值） |
| --- | --- | --- |
| 两盏平行光（太阳、补光） | 强度 0 | 原值 |
| 半球光 | 1.05 | 原值 |
| 曝光 toneMappingExposure | 1.22 | 1.03 |
| 吊顶自发光 | `#efe6d8`，强度 0.32 | — |
| 每个房间的吸顶灯 | 点光源 `#ffe1b8`，强度 24，距离 11，衰减 2；位于吊顶下 0.3 m、房间中心；外观是半径 0.24–0.28 m 的发光圆盘 | 关闭 |

- **主灯**：玩家所在房间那盏灯换成一盏会投影的「主灯」（点光源阴影 1024，`bias -0.002`，`normalBias 0.025`）。玩家走到别的房间，主灯就跟着挪过去。
- **其他房间的灯**：强度为主灯的 75%，不投影，让门洞里看过去也是暖光。
- **透门状态**：门外透过门洞看屋里时（还没进屋），灯光整体按 70% 亮度。
- **避免卡顿**：
  - 灯的数量始终不变；开关灯只改强度，不改 `visible`，否则会触发着色器重新编译。
  - 主灯阴影只在室内时更新（`shadow.autoUpdate`）。

### 3.5 屋内互动（参考图 08–12）

**操作反馈**

- 鼠标悬停在可互动的东西上时：
  - 鼠标变成手指；
  - 这件东西的所有零件加发光 `#3b2a14`；
  - 鼠标旁提示当前能做的动作。
- 点击执行动作，再点一次恢复原状。
- 只响应 6 m 以内的物体；射线遇到的第一个可见物体决定点到了什么，不能隔着墙点。

**互动清单**

| 物体 | 怎么识别（用家具已有的 `userData.part` / `kind`） | 提示 | 动作 | 声音 |
| --- | --- | --- | --- | --- |
| 厨房水龙头 | `mkSingleSink` 里的 `sink-faucet`，加上龙头上的小零件 | 开水龙头 / 关水龙头 | 出水口到池底一根半透明水柱（`#cdeaf6`，透明度 0.72，半径 9–13 mm），轻微抖动；池底一圈扩散的涟漪 | 流水声（循环） |
| 浴室水龙头 | `bathroomVanity` 里高度超过 1 m 的镀铬零件 | 同上 | 同上，流到台盆底部 | 同上 |
| 马桶 | `compactToilet`，点任何部位都算 | 冲水 | 水箱按钮下压；碗里的水面（带漩涡纹理）旋转、下降、缩小，2.8 s 后恢复；冲水期间再点无效 | 冲水声 |
| 吸顶灯 | 每个房间的灯盘 | 关灯 / 开灯 | 这个房间的灯和灯盘一起关掉或打开，阴影随之变化 | 开关声 |
| 落地灯 | `hhTripodLamp` | 开落地灯 / 关落地灯 | 灯罩自发光 `#ffc477`；灯罩里一盏点光源，强度 7，距离 6 | 开关声 |
| 抽屉 | 见下方「抽屉和柜门怎么识别」 | 拉开抽屉 / 关上抽屉 | 沿正面方向滑出：取「家具深度 × 0.6」和 0.32 m 中较小的值，0.45 s | 滑动声 |
| 柜门 | 同上，零件名为 `cabinet-door`，或面板高度 > 0.45 m | 打开柜门 / 关上柜门 | 绕外侧竖边向外转开 1.75 rad，0.65 s | 滑动声 |
| 灶台 | `mkDoubleGas` 的 `control-knob`，每个旋钮对应横向位置最近的炉头 | 点火 / 关火 | 旋钮转动；炉头上一圈 14 个跳动的蓝色火苗；一盏蓝色小点光源，强度 0.2 | 开关声 + 燃气声 |

**抽屉和柜门怎么识别**

识别要通用，不要按具体家具写死。游戏以后加的同类家具，应该自动就能用。

1. 家具的正面方向：取家具局部 +Z 方向，换算到世界坐标后，取最接近的坐标轴。
2. 找把手：满足以下全部条件的零件——
   - `userData.paintable === false`；
   - 最长边 < 0.4 m；
   - 位于家具正面 9 cm 以内；
   - 不是灶台旋钮。
3. 找面板：每个把手背后，找满足以下全部条件的零件——
   - 可涂色；
   - 不是台面（`supportTop`）；
   - 在正面方向上覆盖把手的位置；
   - 位于把手后方 12 cm 以内；
   - 横向宽度 > 0.2 m。

   有多个时，零件名是 `drawer-front` / `cabinet-door` 的优先，其次选体积最小的。
4. 随面板一起动的零件：位于面板范围内、在面板前方的装饰件，比如凹槽、内嵌面板、把手。
5. 补抽屉盒：游戏里很多抽屉只画了一块前板。前板厚度 < 0.1 m 时，在它背后补一个开口的抽屉盒，拉开后能看到：
   - 底板、两侧板、后板，板厚 12 mm；
   - 颜色 `#e7d2ae`；
   - 宽、高各比前板小 5 cm；
   - 深度取「家具深度 − 0.12 m」和 0.34 m 中较小的值。
6. 状态不写存档。

原型在 `house` 场景里识别出 18 个可互动物体：

- 1 盏落地灯；

- 2 个灶台抽屉；
- 1 个厨房水龙头；
- 2 扇水槽柜门；

**声音**

- 全部用 WebAudio 现场合成，不需要音频文件：白噪声加滤波器，参数见 `roam.js` 中的 `sfx()`。
- 第一次点击之后才创建 AudioContext。
- 设置里如果有「静音」，也要对这些声音生效。

### 3.6 界面

1. 进屋后：
   - 隐藏标题卡、「自动 / 外观 / 室内」、「慢慢转」、「回到全景」；
   - 显示顶部居中的提示条：「W S 前后 · A D 左右 · E Q 升降 · Shift 加速 · 拖动看四周 · 点地面走过去 · 点水龙头、马桶、灯、抽屉、柜门、灶台可以用 · 可以穿墙 · Esc 出门」；
   - 右下角显示「出门」和「?」。
2. 「?」帮助卡的内容，见原型 `index.html` 中的 `#help`。
3. 颜色和字体沿用上一包的暖纸色系 token，不新增颜色。

### 3.7 性能

1. 按需渲染：没有移动、没有动画时不渲染。有动画（水流、火苗、开关门）的时候每帧渲染。
2. 主灯阴影只在室内更新；外观状态不渲染室内（室内组隐藏）。
3. 目标：1440×900、普通教室电脑的集成显卡，室内移动不低于 45 fps。回传时附上测得的帧率和测试机器配置。

## 4. 不在本次范围

以下内容本次不做，不要提前实现：

- 墙上的电灯开关；
- 在床或沙发上坐、躺；
- 抽屉里放东西；
- 机器人走动；
- 阳光透过窗户投在地上的光斑；
- 二楼和楼梯（如果房子有多层，先只做一楼，二楼的显示规则另行设计）；
- 墙后描边（X-ray），负责人已否决。
