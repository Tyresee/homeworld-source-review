## 任务 1：墙面系统

每个房间的墙可以分别选「样式」和「颜色」。参考图和生成方式见 `review-walls-2026-10-30/README.md`。

### 1.1 选项

样式（只做这 3 种）：

| id | 名称 | 规格 |
| --- | --- | --- |
| wall-plain | 素色乳胶漆 | 几乎无纹理，只有极轻的明暗斑驳 |
| wall-stripe-fine | 细条纹壁纸 | 竖条纹，间距 10 cm、条宽 5 cm，深浅差约 5% |
| wall-dots | 小圆点壁纸 | 错位圆点，间距 12 cm、直径约 2.8 cm，比底色暗约 14% |

颜色（5 种）：

| id | 名称 | 色值 |
| --- | --- | --- |
| wall-warm-white | 暖白 | #f4efe6 |
| wall-apricot | 杏粉 | #f1d9cc |
| wall-mist-blue | 雾蓝 | #d4dfe7 |
| wall-lavender | 薰衣草 | #e1dbe8 |
| wall-slate-blue | 灰蓝 | #a8b8c4 |

样式和颜色分开存储，可以任意组合，共 15 种。

### 1.2 纹理规则

1. 纹理以白色为底，渲染时乘以墙色。
2. 按世界尺寸平铺：横向每 1.2 m 一个周期，纵向覆盖整面墙高 2.85 m。挤出墙体的 UV 已经是米制，直接设 repeat；平面墙和盒体墙按实际长度计算 repeat。
3. 墙面纹理不能和家具共用贴图（例如 linen）。
4. 使用固定随机种子生成，生成后缓存。

### 1.3 默认值与兼容

1. 所有房间默认使用 wall-plain + wall-warm-white，浴室也一样（warm 主题中原来的 ceramic 墙面改为素墙）。
2. 存档中按白名单校验样式 id 和颜色 id。字段设计由你决定，回传时说明。
3. 旧存档的处理：
   - 没有刷过墙色的 → 使用默认值
   - 刷过墙色的 → 保留原来的颜色，样式用 wall-plain
   - 不改写旧数据

### 1.4 界面

1. 右键墙面时出现「墙面」子菜单：上排是 3 种样式（带缩略图），下排是 5 种颜色。
2. 点击后立即生效并保存。
3. 本任务免费，不新增 SKU。

### 1.5 look-dev 调色页

1. 增加墙面样式和墙面颜色两个控件，可以逐个房间设置。
2. 新增预设 `warm-walls.json`：在 warm-floors 的基础上加上 1.3 的默认墙面。

### 1.6 验收

1. 在调色页中渲染 15 种组合（客厅、厨房各一套），与 `review-walls-2026-10-30/renders/` 里的同名图对比：
   - 条纹、圆点的尺寸、深浅和颜色一致
   - 纹理不会随墙的长度拉伸
   - 家具纹理不受影响
2. 在应用中切换样式和颜色，刷新后选择仍然保留；切换学生后不会串数据。
3. 默认主题和 toy 主题的基准图保持不变。
4. 为白名单校验和旧存档回退补充测试。

## 任务 2：页面界面（配色、投影模式、工具栏）

截图在 `docs/ui-review-2026-10-30/screenshots/`。

- `01`–`04`：现状
- `05`–`08`：建议效果，用原型 CSS/JS 叠加在真实页面上截取

原型文件：

- `prototype/skin.css`：配色和字号
- `prototype/dock.js`：图标工具栏
- `prototype/ui-harness.mjs`：本地启动页面用的假平台，只含虚构数据

### 2.1 去掉界面上的绿色，改用暖纸色系（参考截图 05）

现在侧栏、选中状态、主按钮、背景渐变和遥控器屏幕都是绿色，和 warm 场景冲突。请改用下面的 token，取值参照 `skin.css`：

| 用途 | 色值 |
| --- | --- |
| 底色 | #f6f2eb |
| 面板 | #ffffff / #fbf9f5 |
| 描边 | #e8e0d4 |
| 主文字 | #2b2622 |
| 次文字 | #8a7f72 |
| 强调（主按钮、选中描边） | #b9755a |
| 选中底色 | #f4e4d9 |
| 积分图标 | #e0a64a |

- 场景背景：从中心 #fbf9f5 向外渐变到 #e7dfd2。
- 机器人遥控器：
  - `.home-quick-screen` 的墨绿渐变改为炭色系，例如从 #4a4440 到 #2b2622
  - `--remote-ink` 改为 #33302c
  - 彩色动作按钮保持不变
- 改成 CSS 变量，挂在 warm 主题下。

### 2.2 投影模式（参考截图 06）

1. 新增一个开关，例如 `?view=present`，或者页面上的一个按钮加快捷键 `P`。
2. 开启后隐藏顶栏和左侧学生名单，场景铺满整个窗口。
3. 学生切换改为标题旁边的下拉菜单。
4. 窗口尺寸变化后，相机重新取景。

### 2.3 字号（投影可读）

- 正文最小 16 px，说明文字最小 14 px
- 标题 30 px
- 积分数字 32 px 以上，前面加金币图标；积分变化时数字滚动约 0.6 秒

### 2.4 用图标取代顶部那排文字按钮（参考截图 07、08，见 `dock.js`）

| 现在的按钮 | 改为 |
| --- | --- |
| 室内 / 户外 / 整栋 | 左下角的图标坞：三个 64 px 插画图标（沙发 / 小树 / 小房子），下方配短字；选中项用 #b9755a 描边 |
| 衣橱、机器人配色 | 收进机器人遥控器，新增一项「打扮」 |
| 挥手 | 删除，遥控器里已有这个功能 |
| 聚光灯舞台 | 「表演时间」按钮：深色底、聚光灯图标，放在图标坞右侧 |
| 重置镜头 | 右下角镜头组：放大、缩小、准星（回到默认视角），每个 52 px |

补充要求：

1. 放大和缩小要接到现有的缩放逻辑上；原型里这两个按钮还没有接通。
2. 老师快捷键：`1` / `2` / `3` 切换三个视图，`0` 重置镜头。输入框获得焦点时快捷键不生效。
3. 原有按钮的 id 和行为可以保留在 DOM 中供测试使用，但不要显示出来。
4. 底部那行常驻的操作提示改为一个「?」帮助按钮；状态消息改为几秒后自动消失的提示条。

### 2.5 约束

- 不重新引入已经否决的常驻底部条或右侧大面板。
- 左键打开遥控器、右键打开菜单、拖动、空格平移、滚轮缩放等现有操作规则一律不变。
- 右键菜单的重新分组不在本次范围内，会另出设计稿。

### 2.6 验收

1. 在 `?theme=warm` 下截取以下画面，与截图 05–08 对比，要求布局和配色一致：
   - 普通模式
   - 投影模式
   - 打开遥控器
   - 切到整栋视图
2. 1440×900 和 1920×1080 两种窗口下不出现遮挡和溢出。
3. 快捷键在输入框内不会触发。
4. 默认主题和 toy 主题的页面截图保持不变。
5. 核心测试全部通过。
